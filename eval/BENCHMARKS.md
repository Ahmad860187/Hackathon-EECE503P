# Evaluation cases: provenance and licences (dev only)

Everything under `eval/` is development-time material. None of it is read by `agent.py`, and nothing
paper-specific from here may be copied into prompts, templates or the kit (brief: "paper-specific
prewritten answers or generated pages are not allowed").

All case folders are generated by `python eval/build_cases.py`, which holds the case text, excerpts,
reference formulas, must-mention facts and quizzes in one reviewable file. Each folder contains:

| File | Purpose | Given to the agent? |
|---|---|---|
| `case.json` | the three required strings (`source_url`, `focus`, `audience`) | yes |
| `excerpt.txt` | a short paraphrase or public-domain quotation of the source (≤ 300 words), for the "excerpt available" condition | yes, unless `--no-excerpt` |
| `reference.json` | independently computed expected values, must-mention facts, common errors, a 5-question quiz | **never** |

Accessed 2026-10-03. Reference values are computed in `build_cases.py` with plain formulas (stdlib
`math`/`cmath`, RK4 where an ODE is involved). They are independent of the agent and of any model.

## 2. Benchmark-derived generalisation cases (`bench_*`)

These cases deliberately cover fields that are absent from the core set: molecular physics and
chemistry, materials and crystallography, semiconductor devices, photonics, data converters,
thermodynamics, and surface chemistry. Each is scoped to a small-input mechanism.

### SciCode (Tian et al., NeurIPS 2024 D&B, arXiv:2407.13168)

- Dataset: https://huggingface.co/datasets/SciCode1/SciCode (files `problems_dev.jsonl`, 15 problems with gold
  code; `problems_test.jsonl`, 65 problems without gold code). Code: https://github.com/scicode-bench/SciCode.
- Licence: **Apache-2.0** (both the HF dataset card and the GitHub repo).
- Access outcome: **reachable.** Both JSONL files were downloaded. The numeric test targets live in
  `test_data.h5`, which is distributed separately through Google Drive. It was **not** downloaded, so the
  targets are recomputed:
  - dev problems (38, 47): by our formulas, then **cross-checked by executing SciCode's gold code**, which
    matched to all printed digits (U_ij = 48384, 5075.94…, 0; U_i = 13.6256…; every reciprocal vector).
  - test problems (34, 39): by our own implementation of the scientist-written background formulas. The DBR
    result was cross-checked at the Bragg wavelength against the closed form R = tanh²(N ln(n1/n2)), and
    the two agree.
- Test inputs are copied verbatim from each step's `test_cases` into `reference.json → settings`. The
  `benchmark` block in each file records the problem id, steps and split.

| Case | SciCode problem | Field |
|---|---|---|
| bench_lennard_jones | 47 Internal_Energy (steps 47.1–47.3; dev) | molecular simulation / chemistry |
| bench_reciprocal_lattice | 38 Reciprocal_lattice_vector (38.1–38.3; dev) | materials / crystallography |
| bench_pn_junction | 34 PN_diode_band_diagram (34.1–34.3; test) | EE / semiconductor devices |
| bench_dbr | 39 Reflection_spectra_for_a_Distributed_Bragg_Reflector (39.1–39.3; test) | photonics |

Notes: SciCode 34's docstrings label N_a and N_d inconsistently. We follow the physics, with N_a as the
acceptors on the p side. SciCode 34.2 gives the electron charge as "×10^-19 C"; we use 1.6e-19 C.

### TheoremExplainBench (Ku et al., ACL 2025, arXiv:2502.19400)

- Dataset: https://huggingface.co/datasets/TIGER-Lab/TheoremExplainBench (240 theorems: 60 each in math,
  physics, comp_sci and chemistry; fields uid, subject, difficulty, theorem, description, subfield).
  Code: https://github.com/TIGER-AI-Lab/TheoremExplainAgent.
- Licence: **MIT** (HF dataset card and GitHub repo).
- Access outcome: **reachable.** The full list was read through the HF datasets-server API. The
  descriptions are only one or two sentences, so each excerpt adds a paraphrase of the standard result,
  and `source_url` points to the primary paper or lecture.
- Selection rule: Hard or Medium theorems from fields not already covered, each explainable as a
  quantitative mechanism with a handful of inputs and no dataset.

| Case | TEB uid | Theorem (subject / subfield) | source_url |
|---|---|---|---|
| bench_sigma_delta | theorem_207 | Sigma-Delta Modulation (comp_sci / DSP, Hard) | Inose, Yasuda, Murakami 1962 (DOI) |
| bench_van_der_waals | theorem_190 | Van der Waals Equation (physics / Thermodynamics, Hard) | van der Waals Nobel lecture 1910 (PDF text checked) |
| bench_langmuir | theorem_233 | Langmuir Adsorption Isotherm (chemistry / Physical Chemistry, Hard) | Langmuir 1918 JACS (DOI) |

TheoremExplainBench's own metrics (accuracy and depth, logical flow, visual relevance, element layout,
visual consistency) informed criteria A–C in `eval/RUBRIC.md`.

### Paper2Poster / PaperQuiz (Pang et al. 2025, arXiv:2505.21497)

- Method only; no data is used. Code is MIT (https://github.com/Paper2Poster/Paper2Poster).
- `scripts/quiz_eval.py` borrows the PaperQuiz idea. A separate model reads only the generated page's text
  and answers 5 multiple-choice questions written from `must_mention` facts. Option E ("the page does not
  say") penalises prior knowledge, and `--baseline` measures how much the model knows without the page.
